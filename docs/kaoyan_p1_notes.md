## 两层怎么算

**L0 意图**：拿最后一轮问句跑 `detect_kaoyan_intent`，和 `expected_intent` 逐字段比：

- `schools`、`codes`、`year`：集合或值相等。识别器把 4 位学科代码（0812、0839）放在 `prefixes`，这里并入 `codes` 一起比
- `operation`：由识别出的 kinds 推出（export > filter > compare > lookup）
- `metrics`：金标准写了才比，要求是识别 kinds 的子集；迁移来的 v1 题没写，不计
- `privacy`：`expected_refusal == "privacy"` 和识别结果是否一致
- `exact`：一道题所有参与的字段都对

**L1 工具**：只算有 `expected_facts` 的题。用金标准的学校、代码、年份、指标替换识别结果，交给 `structured_calls` 生成调用，真实调用工具，再在输出里找 `table + program_id + kind + year + value` 都相同的事实。来源 `source_doc_id` 单独统计，不影响命中。

如果工具输出里一个带 `program_id` 的专业都没有，而调用的是 `compare_programs`，这道题记为“暂不可评”，不算缺失。实际上 `compare_programs` 除了中文表格行还附带结构化的 `programs`，所以对比题能评（见下文 v1 回填）。

## 基线怎么更新

`docs/eval/baseline.json` 只存汇总数。题目增删、口径调整会让比例合理地变化，这时在同一个 PR 里重写基线，并在 PR 说明里写原因：

```bash
python scripts/seed_kaoyan.py --db /tmp/kaoyan.db && python scripts/extract_kaoyan.py --db /tmp/kaoyan.db
python scripts/eval_kaoyan.py --db /tmp/kaoyan.db --out docs/eval --write-baseline docs/eval/baseline.json
```

用新建的库而不是本机 `data/kaoyan.db`，因为 CI 用的是新建库（本机库多了 OCR 抽出的事实）。

## 对抗集（2026-10-10，分支 `p1/adversarial`）

计划要求 8 类陷阱、每类 ≥10 道。写了 80 道（`data/gold/adversarial_m1.json`），`--adversarial`（后改名 `--specs`）生成 `adv-*` 行，`split=adversarial`。规则和陷阱说明见 `data/gold/README.md`。

**事实不手抄。** 题里只写“专业|表|口径|年份”，值和来源由脚本从库里取，只认 `verified=1`；取到两个不同的值就报错。第一次生成就拦下一条：中大 085400 的 2025 学院线 370 在库里是 `verified=0`。对照 `sysu_sece_2025_复试录取实施细则.html`，原文确实是 370（以及计划 95 / 推免 24 / 公开 71），未核对只是因为 2025 年没有人工种子。这条用 `checked` 标记放行，原文写进 `checked_notes`。

**跑完先查金标准。** 第一次跑完逐道看了 L0、L1 的失败，改了 5 处我自己写错的意图：

| 题 | 改动 | 理由 |
|---|---|---|
| noexam-02、noexam-06 | `codes` 补 083900 | “中大网安学硕”能唯一对应 083900；追问题已经按“解析后的意图”记代码，这里保持一致 |
| oos-04、oos-06 | `operation` compare → lookup | 另一所学校不在范围内，实际只查一所 |
| noexam-04 | `operation` lookup → filter | “有哪些专业能统考”是筛选，和 noexam-07 一致 |

和用户交互定的四条规则：不带姓名的逐人分数不算隐私（priv-07、priv-09 改为不拒答，但库里只有统计，要如实说明）；未发布年份可以补最近一年的数但要标年份；一边超范围的比较题记 lookup；两个年份时记问的那一年，两年都比时记 null。核对人记为用户和 agent。

**评测分组。** 报告和基线现在除了总体，还按切分（`by_split`）和陷阱（`by_trap`）分别汇总，CI 的 2 个百分点回退门槛对每一组都生效，对抗题不会拉低 dev 的数，也不会被总体平均掩盖。

## 冻结 test 和已知失败清单（2026-10-11，同分支）

用户要求先冻结 test 再修 L0，并确认加题没有把回退门槛悄悄放低。

**第 12 题先核了年份。** scnu-017（报名人数表）发在“往年数据”栏，发布时间 2025-10-15 08:48，是 2026 届网报第一天，所以 294 / 99 是 2025 年入学那一届，48 / 20 是 2026 拟录取，6:1 是跨年相除。`sources.json` 里它的招生年份改为 2025 并补来源页；用 CI 方式重建库对比，事实表一行没变，只有这份文档的元数据变了。sup-12 改为 `unknown_data`，要求分别给数、标年份、说明报名不等于实际参加初试。第 10 题的裁判要求按用户的四条重写（只列目录导师、标年份出处、不评价不排序、不补库外信息；列出导师不等于有专硕名额；另外三校说未取得）。

**test 切分**：90 道 `rv-*` / `sup-*` 里按“学校 × 类别”分层抽 30%，得到 26 道（16 道模板题、10 道补充题，覆盖 14 层），规则和排除项见 `data/gold/README.md`。sup-07、sup-29、sup-36（L1 修复目标）和 sup-10（导师试点）不进 test。之后评测默认不跑 test；`--split test` 只给总分。补充集里 L0 没对上的题，冻结前已经逐题看过，其中一部分进了 test，这一点没法撤回，只能从现在起不再看 test 的逐题结果，修 L0 只按能力泛化。

**门槛有没有被放低。** 用加补充集前后的两份报告逐题比，原来的 148 道题里没有一道从对变错：L0 仍是那 32 道失败，L1 仍是那 2 道。但比例门槛确实松了：L0 总体基线从 78.4% 降到 71.3%，unsplit 组 90 道里错一道只掉 1.1 个百分点，低于 2 个点的阈值，不会报警。所以 baseline 里加了逐题的 `known_failures`：清单外的失败、清单内多错的字段或多缺的事实，都直接让 CI 失败；清单里的修好了也要求重写基线，清单只会主动缩小。

## L1 四个失败（2026-10-11，同分支）

按用户给的顺序修，每条都按能力改，不针对单题：

| 题 | 问题 | 改法 |
|---|---|---|
| sup-29 | 匹配超过 6 个专业时 `search_programs` 返回精简视图，只剩派生的统招估计，计划数和它的口径全丢了 | 精简视图保留每条计划数：`kind`、`label`（口径名）、年份、数值、上限/统筹标记、来源（doc_id、url、页）。只去掉口径定义全文和证据原文 |
| sup-07 | 一句话两个代码时 `structured_calls` 只按学校查，代码丢了 | 查询型意图有多个代码时，按代码各发一组调用（学校、学院不变） |
| adv-bd-05 | 筛选只返回被筛掉的个数，085400 为什么不算（考 884）没有证据 | 新增 `excluded_programs`：每个被筛掉的专业给原因，和导致它被筛掉的科目组或统招依据；`excluded` 仍是个数，接口兼容 |
| sup-36 | 没有反向筛选 | `search_programs` / 工具 / `GET /v1/programs` 加 `exclude_subject`；意图识别把“不考 / 不用考 + 科目”转成它（408 仍走 `is_408=False`，数学一/二、英语一/二转成代码）。科目未知的专业进 `unknown`，不算“不考” |

### L2 检索评测设计（只是设计，还没跑）

**题池。** 补充集里已有 8 道文档题，加上草稿审完留下的 doc-only 题（现为 29 道）。doc-19 改成结构化题，不进 L2。

**切分，跑之前先冻结。** 已有的 8 道沿用现有切分：sup-09、sup-19 已在 test，其余 6 道在 dev，不重新抽。草稿题审完后按“题型（单校 / 不带校名 / 跨校 / 原文无答案）× 二元组重合度分层”抽约 30% 进 test，用和 M1 相同的内容摘要冻结。现在的 `--freeze-test` 只能用一次，所以要加一个“追加冻结”的入口，只允许新增 test 行，不改已冻结的行。冻结后才跑 BM25 和 hybrid。test 只出总数，不看逐题。

**命中怎么算。**

- 文档级：top-k 块所属文档里，命中任一 source 记 any@k，命中全部 source 记 all@k。有两个及以上 source 的题（doc-08、09、13，跨校题 doc-23～28）两者都报；只有一个 source 的题两者相同。
- 块级：以 evidence 片段为准。某片段的字符二元组有 ≥80% 落在同一个 top-k 块里，算这个片段被命中；这样能容忍片段被切块边界切开。块级同样报 any（任一片段命中）和 all（全部片段命中）。
- k 取 3、5、10。

**两种过滤各跑一遍。** 带学校过滤时，用题目 gold 的 schools 当 `school` 过滤条件；跨校题多个学校时，每校各检索一次再合并。不带过滤时直接检索。不带校名的题两种跑法相同，单列。

**按问题和证据的字面重合度分层。** 先用 `normalize_text` 归一化，再去掉标点，问题的字符二元组集合记作 B(q)，所有 evidence 片段拼起来的字符二元组集合记作 B(E)，重合度 = |B(q) ∩ B(E)| / |B(q)|。分三层：低 [0, 0.1)、中 [0.1, 0.3)、高 [0.3, 1]。阈值在算重合度之前就定死。评审算出平均约 0.26，doc-02、07、14、18、21 接近 0。

**报数方式和禁止事项。**

- 报命中数，例如“any@5 命中 21/37”，按层、按题型、按过滤方式分开列，不报百分比，题少时百分比会误导。
- 不用这批题调切块大小（现为 800）或融合权重（RRF k=60），全部用当前默认值。真要调参，另找一批不进评测集的题。

**在哪跑。** BM25 不需要模型，放进 CI：索引只建在已入库的原文上，含个人信息的文件和 >3MB 的 sysu-072 在 CI 里没有。跑之前先检查每道题的 sources 是否都在 CI 索引里，不在的题在 CI 报告里标“跳过”并计数，不算不命中。hybrid 要向量模型，只在本机跑，和 BM25 用同一份冻结切分。
